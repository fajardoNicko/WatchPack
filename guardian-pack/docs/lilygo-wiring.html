How this was verified (2026-10-05). Header order taken from LilyGO's own schematic T-A7670X-V1.4.pdf (connectors PX and PY), GPIO roles from LilyGO's pin table for the A7670G-GPS version, the ExternalGPS_A7670G_Only example and the Extern-GPS-Module schematic — then checked pin by pin against the silkscreen visible in your photos. Every label that is readable on your board matches.

What was wrong in the old version

SOS button on IO19. IO19 is the GPS module's WAKE_UP line. Your button is normally closed, so at rest it would hold WAKE_UP low = GPS permanently asleep = no location in any SOS SMS. Button moved to IO32.
IO23 shown as "spare". It's the GPS 1-PPS output. IO21/IO22 ("verify") are confirmed taken: GPS serial. On this board only IO18 and IO32 are free and can drive an output.
Pin order on both headers was wrong. It was an ESP32 DevKit layout (EN, IO16, IO17, TX0 in the wrong places). Redrawn below from the V1.4 schematic.
Antenna sockets drawn at the ESP32 end. LTE socket is on the front, at the modem end, marked RF. GPS socket is on the small upright GPS board on the back. The GNSS spot on the main board is empty — the A7670G has no GPS inside.
"Wire by the silkscreen label." On V1.4 the battery holder and GPS board hide most labels (IO18, IO19, IO21–23, IO5, IO34, IO26, IO27, IO4, IO2, IO15, IO14). Now: identify the edge, count from the ESP32 end, cross-check against the labels you can read.
Button assumed normally-open. Yours says Momentary Push Button Normally Closed. Wired to GND with INPUT_PULLUP: idle reads LOW, pressed reads HIGH. The firmware handles it — nothing to buy.
Buzzer moved IO32 → IO18. The SOS button needs IO32 because it's an RTC pin: it can wake the ESP32 from deep sleep. IO18 can't.
Small fixes. Charger is a CN3065 (500 mA) + DW06D protection, not a TP4056. The 5 V pin is VBUS (5 V max), not VIN.

Find your bearings first (never use "left/right" — flipping the board swaps them)

  • ESP32 end = the end with the silver ESP32 module. All pin positions below are counted 1 → 16 starting from this end.
  • PY edge = the long edge with the ON/OFF slide switch and the white 2-pin socket.
  • PX edge = the long edge with the USB-C port and the RST / IO0 buttons.

Why V_BAT and not 3.3 V: the buzzer needs 4–8 V. On battery the board's highest available rail is V_BAT (about 3.6–4.2 V), so it will beep, a bit below its full 85 dB. The 3.3 V rail would be quieter, and it also powers the ESP32 and the GPS, which shouldn't share it with a noisy buzzer. Peel the "REMOVE SEAL AFTER WASHING" sticker off for full volume. A 1 kΩ resistor in series with the SOS button is optional insurance: if a wire ever lands on 3.3 V by mistake, it limits the current to 3 mA.

How to make the connections (Phase 2 — after the software tests pass)

  1. Photograph the back silkscreen before soldering anything.
  2. Solder header pins only where you need them — snap single pins off the supplied strip: PY positions 2, 3 and 16, PX positions 9 and 15. With no pin on 3.3 V, VBUS, IO4, IO5 or IO12, you physically can't plug a wire onto the wrong one.
  3. Push each pin in from the back (battery side), so it points that way, and solder it on the front. That keeps the iron away from the battery holder and the GPS board.
  4. Your jumpers are female–female. For the button: cut one jumper in half, strip 5 mm, solder it to a button lug, and insulate it. Do the same for the second lug. The female ends plug onto the pins.
  5. Check the button with a multimeter (continuity mode) before connecting it: it should beep when not pressed and go silent when pressed.
  6. Buzzer driver (Figure 3): solder the 1 kΩ resistor to the transistor's base leg, and the buzzer's (−) leg to the collector. Then add cut jumpers for A (resistor end), B (emitter) and C (buzzer +). Cover every joint with heat-shrink so no two legs can touch. Send me the listing or a photo of the transistor before soldering — the leg order (E-B-C) varies between part numbers.
  7. Run the pin-test sketch (it prints the button state and beeps the buzzer) before anything else uses these pins.
  8. Checkpoint: send a photo of your soldering before you power up.

Before the first power-on — in this order

Board unpowered: USB unplugged, switch on OFF.

  1. LTE antenna → u.FL marked RF on the front at the modem end. Line it up straight and press down until it clicks. Never run the modem without it.
  2. GPS antenna (the square patch) → the u.FL on the upright L76K GPS board on the back. It's an active antenna, which is what this board needs. In use, the beige ceramic side with the silver dot faces the sky.
  3. u.FL plugs are fragile (~30 plug cycles). To remove one, lift it straight up by the connector body — never pull the cable.
  4. Nano-SIM: test it in a phone first — PIN lock off, has load and a data promo. Insert it before power-on, or the modem won't see it.
  5. 18650 cell: flat (−) end to the ESP32 end (white "−" bar near PY1), button (+) end to the LILYGO-logo end (white "+"). If you have a multimeter, check the cell reads 3.0–4.2 V first.
  6. Cable: USB-A → USB-C into the board's USB-C. Not the micro-USB on the back.

Never

  • Connect anything to IO4, IO5 or IO12 (modem power key, modem reset, power enable). LilyGO says the same about IO4 and IO5.
  • Use IO19, IO21, IO22 or IO23. They belong to the GPS module.
  • Connect 3V3, VBUS or V_BAT to GND, or put more than 5 V into VBUS. V_BAT is wired to the battery — treat it as live whenever a cell is inserted, whatever the switch says.
  • Plug a battery into the white 2-pin socket. It only takes a 5–6 V solar panel.
  • Add a TP4056, MT3608, 1000 µF capacitor or any regulator. This board already has all of them. wiring-corrected.html is for a different build.
  • Leave a microSD card inserted while uploading.
